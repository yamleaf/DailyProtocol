# 双端界面重构实施方案（DailyController × DailyTask）

> 范围：控制端（DailyController）+ 被控端（DailyTask）双端 UI 统一重构。
> 共享基座：升级 **DailyProtocol** 仓库为「协议 + 设计系统」共享库（仓库名后续可按需改，如 DailyKit / DailyCore）。
> 本文是落地总方案；被控端导航专项见同仓库 `DailyTask/docs/底部导航重构落地方案.md`。

---

## 0. 关键决策（需拍板）

### D1 — 双端品牌主色不一致（必须二选一）
| 端 | 当前 `md_primary` / `theme_color` |
|----|------|
| 控制端 | `#5B5BD6`（紫） |
| 被控端 | `#4F6EFF`（靛蓝，近期由 `#3399FF` 改来） |

**现状**：被控端 `colors.xml` 已大量对齐 `md_*` 语义色并做了别名桥接（`surface`→`md_surface` 等），差距主要在**品牌主色**和少量语义色（被控端缺 `md_warning`/`md_teal`/header 渐变，背景用 `back_ground_color #F1F1F1` 而非 `md_background #F6F4FB`）。
**建议**：统一为**单一品牌色**。推荐保留控制端 `#5B5BD6`（其色阶已全、引用面广），被控端 `theme_color` 改为 `@color/md_primary` 别名过渡；若你更偏好靛蓝，则反向。D1 不决则 P4 无法收口。

### D2 — DailyProtocol 集成方式
- **推荐**：git submodule，两端 `settings.gradle` 引入 `:dailyProtocol`，真正单源。
- **兼容**：若暂不便改 submodule，保留「复制同步」脚本（现有 3 份 Protocol.kt 同款机制扩展为含 res），但需明确定期同步纪律。
- 仓库可改名，不影响本文结构。

## 1. 架构目标

```
DailyProtocol (library)
 ├─ protocol/crypto (现有：Protocol.kt / SecretBox.kt / MqttSigner.kt …)
 └─ design-system (新增)
     ├─ values/tokens.xml        // 颜色（浅）
     ├─ values-night/tokens.xml  // 颜色（深）
     ├─ values/dimens.xml        // 间距 / 圆角 / 尺寸
     ├─ values/styles.xml        // 列表项 / 卡片 / 对话框 style
     ├─ color/bottom_nav_color.xml
     ├─ drawable/bg_status_pill_*.xml   // 5 态药丸背景
     ├─ drawable/bg_list_row.xml
     ├─ layout/item_list_row.xml        // 统一列表项组件
     └─ drawable/ic_*.xml (M3 描边图标集)
        ↓ 被两端依赖
DailyController  ─┐
DailyTask        ─┘  仅保留业务布局，颜色/组件全部引用 @color/md_* / @style/*
```

原则：**令牌与组件只在 DailyProtocol 定义一次**；两端布局删掉本地重复定义，改为引用。旧名通过别名桥接，保证过渡期不崩。

| `md_surface` | #FBF8FF | 卡片面 |
| `md_onSurface` | #1B1B23 | 主文字 |
| `md_surfaceVariant` | #E4E1EC | 次级面 |
| `md_onSurfaceVariant` | #46464F | 次级文字 |

> 被控端现有历史色（`ios_green`/`text_hint_color`/`text_default_color`/`back_ground_color` 等）在 DailyProtocol 中以别名重定向到上述 `md_*`，代码不必全改。

### 2.2 间距 / 圆角 / 尺寸（`dimens.xml`，沿用被控端已有标尺）
- 间距：4 / 8 / 12 / 16 / 20 / 24 / 32 dp（被控端 `dp_*` 已全覆盖）
- 圆角：**卡片 16**、统计卡 12、**药丸 8**、图标容器 12、对话框 20、底部导航卡 **24**、bottom sheet **28**（被控端 `radius_xl=20` 作为对话框/导航基线）
- 触控：列表项高 60dp、最小触控 48dp

### 2.3 排版（新增，两端统一）
| 角色 | 字号 | 字重 | 说明 |
|------|------|------|------|
| 设备名 / 大标题 | 17–19sp | 700 | 控制端概览/被控端 Hero |
| 区块标题 | 15sp | 500 | SectionTitle |
| 正文 | 14sp | 400 | 列表项/按钮 |
| 次级说明 | 12–13sp | 400 | 副标题/helper |
| ID（等宽） | 13sp | 400 monospace | 设备ID/ broker |
| AppBar | 20–22sp | 500 | 工具栏标题 |

### 2.4 层级（elevation）
- surface 1dp / raised 3dp / FAB·底部导航 6dp（控制端底部导航卡已用 6dp，对齐）

### 2.5 状态语义
- **5 态药丸**：在线(#2E9E63) / 配对中(主色) / 离线(#9A9AA5) / 低电量(#FA8C16) / 异常(#BA1A1A)，两端共用 `bg_status_pill_*.xml`
- **界面态**：加载（skeleton 占位）、空（EmptyView 已存在，统一样式）、错误（重试卡 + 主操作按钮）、成功（Snackbar，非 Toast 横幅）

### 2.6 组件库（在 DailyProtocol 落地，两端复用）
列表项 `item_list_row`（图标圆角方 + 标题 + 副标题 + 末尾值/箭头/开关）、卡片、开关行、对话框、底部导航、FAB、chip、badge、segmented、搜索条、Snackbar、progress、tooltip、divider。
> 控制端已有 `item_device`/`item_setting_row`；被控端手写开关行——统一收敛到 `item_list_row` + 开关变体。

### 2.7 图标
统一 M3 **描边**图标，24dp，填充仅用于强调态。补齐被控端缺的 `ic_list`/`ic_cloud`/`ic_settings` 等。

### 2.8 动效
- 时长：200 / 300 / 400ms；曲线：standard / emphasized / decelerate
- 底部导航切换 200ms；Tab 内容淡入；`reduced-motion` 全局降级（系统开启时关闭呼吸/位移）

### 2.9 深色模式
令牌按**浅/深双值**从第一天定义（见 3.2），前移为 P0，非后置。

## 4. 分阶段落地

### P0 — 共享基座（不动业务，低风险）
- DailyProtocol 加入 §3.1 全部资源；两端接入依赖
- 两端 `colors.xml` 删除与库重复的 `md_*`，旧名（`theme_color`/`back_ground_color`/`text_*`）改为别名指向库
- 视觉零变化（同名同值），纯搬运
- **回滚**：移除依赖 + 还原本地 colors 即可

### P1 — 被控端导航重构（见专项文档）
- 底部悬浮导航 3 类（任务/远程/设置），默认任务
- 远程从设置提升为一级；远程页删「关于→控制端下载」迁设置「关于」；设置删「远程控制」入口
- Phase1：三 Activity 各 `<include>` 同一 `bottom_nav_bar.xml`

### P2 — 控制端逐屏
- 设备列表：方案A深化（分组/状态药丸/电量行/搜索 pill）
- 概览 `fragment_overview`：图例卡改为状态药丸；8 段瘦身（电池趋势/最近指令/技术详情收「更多」）
- 设置 `fragment_settings`：行组件化；解绑按钮统一危险样式
- 对话框 `dialog_msg_channel`：套统一圆角/宽度规范

### P3 — 被控端逐屏 + 组件收敛
- `activity_main` / `activity_remote_control` / `activity_settings`：行套 `item_list_row`；远程页拆 3 分组卡
- 应用选择 / 自定义应用 / 时间选择 dialog：套统一规范
- 统一图标为 M3 描边集

### P4 — 品牌色收口 + 深色 + 动效 + 无障碍
- D1 决策落地（两端统一 `md_primary`）
- 补 `values-night`；动效规范接入；48dp 触控 / contentDescription / 对比度 QA

## 6. 验收标准（设计 QA）

- [ ] 双端所有颜色/组件来自 DailyProtocol，本地无重复 `md_*` 定义
- [ ] 状态药丸 5 态两端一致
- [ ] 被控端默认进入「任务」页；远程为一级导航；设置无「远程控制」入口
- [ ] 底部悬浮导航视觉两端一致（圆角/阴影/选中指示）
- [ ] 对话框圆角 20dp、最大宽 320dp、危险操作左取消右确认实色
- [ ] 深色模式下关键屏对比度 ≥ 4.5:1
- [ ] 列表项最小触控 ≥ 48dp；主要状态有 `contentDescription`
- [ ] `reduced-motion` 开启时无位移/呼吸动画

## 7. 风险与注意

1. **库资源命名冲突**：两端已有 `md_*` 与库同名，迁移时必须先抽库、再删本地，避免 `Resource entry is duplicated` 编译失败。
2. **D1 未决则 P4 无法收口**：品牌色二选一需尽早拍板。
3. **submodule 同步纪律**：若用复制同步而非 submodule，需约定同步触发点（如发版前），否则双端漂移。
4. **控制端概览瘦身**涉及信息架构取舍（图例卡教学价值），删除前建议补「首次引导/帮助」承载灯色说明。
5. **Phase 2 Fragment 转换**（若做）：`RemoteControlActivity` 长滚动 + 多 dialog，注意 viewBinding/lifecycle 归属。
